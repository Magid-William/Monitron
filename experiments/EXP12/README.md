# EXP12 - The app icon: the designed logo, as a real multi-resolution .ico

## Summary
Turn the designed `logo.svg` into a proper Windows `.ico` (nine frames) and give the app that
identity everywhere - the exe's icon in Explorer/Alt-Tab, the window icon, and the tray icon - in
place of EXP11's runtime-drawn blue monitor glyph.

## Hypothesis
`logo.svg` can become a correct multi-resolution `.ico` using only the in-box toolchain (a narrow
SVG reader, WPF rasterisation, an ICO container writer) - no renderer on this machine, no download -
and the app then carries it as its exe, window and tray icon. Falsifiable as: the `.ico` contains
the nine frames at the expected pixel sizes; each frame's raster matches the SVG geometry, asserted
on the rendered pixels rather than by eye; `csc /win32icon:` embeds it so the shell reports it for
the exe; Win32 returns it for the window (`WM_GETICON` / `GCLP_HICON`); and the tray keeps its icon
(EXP11's witness, `Shell_NotifyIconGetRect`).

## Methodology & blast radius
- Method: the repo's shape - **pure models** and a **thin adapter**, with a seam for the verifier.
  - `SvgIcon.cs` (pure): reads the narrow SVG subset the logo uses (`d`, `fill`, `fill-rule`,
    `stroke`, `stroke-width`, `transform` as `matrix(a b c d e f)`) into a small draw-list, and
    computes the content bounds. `Geometry.Parse` is the rasteriser's half, kept out of the model.
  - `IcoFile.cs` (pure): the ICONDIR/ICONDIRENTRY container - **BMP** frames (32bpp BGRA + AND
    mask) for sizes <= 64, **PNG** for 128 and 256 - and a reader so the tests parse back what was
    written. The generated bytes are a function of the frames alone, so a re-run is byte-identical.
  - `IconGen.cs` (the rasteriser) + `icogen.ps1` (the tool): SVG -> WPF drawing -> `RenderTargetBitmap`
    at each size -> `IcoFile`. `icogen` is built by `csc` like the other tools and never shipped.
  - `IconAssets.cs` (thin): the embedded `.ico` -> a `System.Drawing.Icon` of a requested size (tray
    16, window 32) and a WPF `BitmapSource`. This is the only part the app reads the OS with.
- The icon is generated **once** and **committed** as `src/Monitorn.App/Monitorn.ico` (a clone builds
  without running the tool); `build.ps1` regenerates it only when it is missing or older than
  `logo.svg`, and now passes `/win32icon:` (Explorer/Alt-Tab) plus `/resource:` (the runtime frames).
- **Cropping**: the artwork occupies only ~37% of the SVG's viewBox (measured bounds
  `(349,362)-(763,753)` in a 1124x1086 canvas), so the renderer fits the mark to the content bounds
  with a small margin rather than rendering the viewBox as-is.
- `TrayIcon.cs` loses `MakeIcon` (the drawn glyph) and uses `IconAssets`; `Program.cs` sets the
  window icon from it. Seam `--icon-report <dir>`: the app's own reading of which frames it loaded.
- May touch: new `src/Monitorn.App/SvgIcon.cs`, `IcoFile.cs`, `IconGen.cs`, `IconAssets.cs`,
  `IconTests.cs`, `icogen.ps1`, `icon-test.ps1`, `verify-icon.ps1`, and `src/Monitorn.App/Monitorn.ico`;
  edits to `build.ps1`, `TrayIcon.cs`, `Program.cs`, `README.md` if it describes the tray glyph,
  `experiments-overview.md` and this file.
- Off-limits: `logo.svg` and `logo.figcraft` (the source of truth, never edited), the
  brightness/schedule paths, the stored `theme=` preference, real sunset/sunrise, per-monitor
  profiles, an installer or code signing, and `src/probe` (stays a plain console exe).

## Open questions (known unknowns)
- [ ] Committed asset or generated every build - default **generated once, committed**; `build.ps1`
      regenerates only if missing/stale.
- [ ] Crop to the content bounds or keep the viewBox - default **crop + ~3% margin** (the mark
      occupies ~37% of the canvas as drawn).
- [ ] Colour - default **faithful to the SVG** (`#000000`), one asset for exe, window and tray; the
      dark-taskbar contrast is measured, and a light tray variant is a follow-up if it is unreadable.
- [ ] Which sizes - default **16, 20, 24, 32, 40, 48, 64, 128, 256** (BMP <= 64, PNG for 128/256).
- [ ] Does EXP11's drawn blue glyph go away - default **yes**, the logo replaces it everywhere (its
      "the icon is a drawn glyph, not a designed logo" boundary becomes obsolete).
- [ ] Small sizes - default **the same geometry at every size** (anti-aliased); revisit only if
      16 px is unreadable.
- [ ] Runtime frames - default **embedded as a resource** (per-size fidelity) **and** `/win32icon:`
      for Explorer/Alt-Tab.

## Learnings
- `Get-Command magick,inkscape,rsvg-convert` - run it before promising an SVG rasterisation: none of
  the three exists on this machine, which is what makes the in-box WPF renderer the only option.
- `Geometry.Parse(d)` hands back a **frozen** `PathGeometry`, and its default fill rule is even-odd -
  `Clone()` it before setting `FillRule`/`Transform`, or the assignment throws "read-only state".
  Also: `FillRule` is on `PathGeometry`, not on `Geometry`.
- `PrivateExtractIcons(file, 0, 128, 128, ...)` (user32) - use it to witness that an exe really carries
  each icon size: it returns the frame Windows would draw at that size, PNG-backed frames included, and
  its pixels match the file's frame exactly (0.0 difference at 16/32/48/128 here).
- `Image.FromHbitmap(iconInfo.hbmColor)` loses an icon's alpha (RGB there is all zero for this mark);
  `DrawIconEx(hdc, 0, 0, hIcon, w, h, 0, IntPtr.Zero, 3 /* DI_NORMAL */)` into a 32bppArgb bitmap is
  what renders an HICON with transparency, and it is the way to compare an icon pixel for pixel.
- Give `Window.Icon` the **largest** frame (256), not 32: WPF turns the single BitmapSource into one
  HICON, and Windows scales it to `SM_CXICON` - at 125% (40 px) the shell's icon then differed from
  the file's 40 frame by 0.02, against 0.10 when the 32 frame was the source.
- `GetSystemMetrics(11)` / `GetSystemMetrics(49)` - the icon sizes Windows draws at on this display
  (40 and 20 px at 125%, 32 and 16 at 100%); compare at those, not at the size you assumed.
- Never name a PowerShell test helper `Diff` - `diff` is an alias for `Compare-Object` and swallows
  the call; `PixelDiff` is what worked.
- A black logo on this machine reads 3.2:1 against the taskbar: `SystemUsesLightTheme=0`, and the
  taskbar strip measured a mean luminance of 0.11.
